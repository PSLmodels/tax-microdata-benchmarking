# Annual growth factors update

This document describes how to refresh the growth factors source data in
`tmd/growfactors/data` and regenerate the growth factors file that
`make data` consumes.

The refresh scripts fetch from live CBO, BLS, SSA, and IRS websites.
They are never run by `make data` or by any test, and they need extra
packages:

```bash
pip install -e ".[growfactors-update]"
```

Do the update as its own pull request, separate from any code change, so
that the data diff is reviewable on its own.

## 1. Refresh the CBO baseline

```bash
make -C tmd/growfactors update-cbo
```

This rewrites `data/CBO_baseline.csv` and regenerates
`docs/CBO_Baseline_Updating_Instructions.md` from
`docs/cbo_instructions_template.md`. The instructions file is also an
*input*: `update/update_cbo.py` parses the URLs recorded in it to work
out which report each variable last came from, so do not delete it.

The script assumes the CBO and SSA page layouts, the spreadsheet
formats, and the BLS API response shape are unchanged. If it errors or
the numbers look wrong, that assumption has broken and the script needs
updating. `docs/CBO_Baseline_Updating_Instructions.md` documents how to
do each update by hand if necessary.

Chained CPI-U values come from a separate CBO tax parameters
spreadsheet. Download it, then:

```bash
python -m tmd.growfactors.update.cbo_chained_cpiu <downloaded.xlsx>
```

That writes the values to standard output for manual entry. Always
inspect a new CBO spreadsheet to see which `CBO_*` data structures at the
top of the script need updating.

## 2. Refresh the SOI estimates

When a new year of SOI data is published, download the Table 1.2, 1.4,
2.1, and 2.3 spreadsheets into one directory, then:

```bash
make -C tmd/growfactors update-soi YEAR=<year> SOIPATH=<directory>
```

This adds a column to `data/SOI_estimates.csv`. Then raise `SOI_YR` in
`build_stage1_factors.py` to the new year.

See `docs/SOI_Estimates_Updating_Instructions.md` for the details of
which spreadsheet cells feed which variable.

## 3. Update the remaining source files by hand

- `data/IRS_return_projection.csv` — from IRS Publication 6187. After
  adding a year, raise `IRS_RET_YR` in `build_stage1_factors.py`.
- `data/benefit_growth_rates.csv` — average benefit amounts by program.
- `data/benefitprograms.csv` — benefit program costs. The extrapolation
  in `benefit_factors()` uses the growth rate between the last two years
  present, so adding years changes that rate.

If the new data extend beyond `EYR` in `build_stage1_factors.py`, raise
`EYR` as well. `EYR` is the last year the pipeline produces, and every
source file must cover the full 2008 through `EYR` span that stage 1
indexes by, except `benefit_growth_rates.csv`, whose missing tail years
are padded with ones.

## 4. Regenerate and review

```bash
# Bump VINTAGE so the previous file stays byte-frozen for reproducibility
make -C tmd/growfactors factors VINTAGE=27
make -C tmd/growfactors test
```

Then wire the new file in by adding an entry to `INPUT_FILE` in
`tmd/create_raw_growth_factors.py` for the relevant `TAXYEAR`, and update
`DEFAULT_VINTAGE` in `build_growfactors.py` and `VINTAGE` in
`tmd/growfactors/Makefile` so the pipeline tests check the new file.

Finally, confirm the full build still passes:

```bash
make clean && make data
```

## Source documentation

- `docs/Stage1_Growth_Rate_Sources.csv` — which source supplies the
  growth rate for each stage 1 variable.
- `docs/CBO_Baseline_Updating_Instructions.md` — per-variable CBO update
  instructions, regenerated by `update/update_cbo.py`.
- `docs/SOI_Estimates_Updating_Instructions.md` — per-variable SOI update
  instructions.
